============================================================
RETRIEVAL VALIDATION — CHUNKING STRATEGIES
============================================================

Three chunk representations were evaluated using the same
evaluation dataset, embedding model, K=2 and retrieval metrics.

                    Precision@2   Recall@2   MRR
rag_demo                0.625        0.875   1.000
rag_chunker_exp         0.750        1.000   1.000
rag_chunker_rebalance   0.750        1.000   1.000
rag_chunker_overlap_exp	0.625	     0.750   0.833
---------------------------------------------------------------------
Observations:

1. Both chunk-based representations outperformed the original
   section-based representation on this evaluation dataset.

2. Paragraph-based and rebalanced target-size chunking produced
   identical retrieval metrics.

3. The rebalanced strategy produced a technically cleaner and
   more controlled chunk representation, but this improvement
   did not translate into measurable retrieval improvement on
   the current evaluation set.

4. Therefore, improved chunk structure does not automatically
   imply improved retrieval quality.

5. The results suggest that knowledge-unit granularity has a
   measurable impact on retrieval quality, while the additional
   rebalancing strategy requires a broader evaluation set to
   determine whether it provides a retrieval advantage.

Architectural Conclusion:

Chunk quality and retrieval quality are related but distinct
concerns.

A chunking strategy should therefore be evaluated at two levels:

    1. Structural quality
       - semantic coherence
       - boundary preservation
       - useful chunk size
       - absence of pathological fragments

    2. Retrieval quality
       - Precision
       - Recall
       - MRR

A structurally improved chunker should not be considered
superior until retrieval evaluation demonstrates a measurable
benefit.

Important:

These conclusions apply to the current dataset and evaluation
set and should not be generalized as a universal ranking of
chunking strategies.

Overlap is not inherently beneficial in RAG. While overlap can preserve contextual continuity across chunk boundaries, it also introduces redundancy and can mix neighboring knowledge units within a single embedding. This can reduce semantic focus and negatively affect retrieval. Therefore, overlap should be treated as an optional optimization whose value must be demonstrated through retrieval evaluation rather than applied by default.
